## Exact remediation

**F1-R1:** Persist the canonical accepted `TRUSTED_INTERRUPTION` sample in a **separate** `interruption_replays[sample_id]` registry. Lookup after validated source identity and after existing accepted-sample `seen`, but **before** the ordinary timestamp watermark. Same ID/payload => `EXACT_REPLAY`, ID with changed canonical payload => `CONFLICTING_REPLAY`; neither changes streaks nor last trusted time. The original good/bad `seen` registry remains unchanged. Valid good/bad corrected data using a previously applied interruption ID is intentionally rejected as `CONFLICTING_REPLAY`; there is no correction protocol.

**F1-R2:** `snapshot_version: 2` serializes `interruption_replays` and `restore()` checks type, <=256 registered IDs and no collision with `seen`. Legacy v1 snapshots **without** interruption audit may restore; v1 with interruption audit is rejected `LEGACY_INTERRUPTION_REPLAY_UNAVAILABLE` because audit is diagnostic and cannot reconstruct canonical replay identities. This is a compatibility change limited to the offline mock. Caller-supplied untrusted snapshot JSON is not cryptographically protected.

**Retention:** Maximum **256 interruption IDs** per Lifecycle; no eviction and no time-based pruning. On capacity exhaustion every *new* ID returns `INTERRUPTION_REGISTRY_FULL` and is rejected without control-state mutation. Previously recorded IDs still reject exact/conflicting replay. This deliberately **halts the mock** rather than silently allowing replay to reset a streak after eviction. No automated reset, recovery policy or production persistence. The existing accepted-sample `seen` remains separately unbounded and is outside D3.

**Scope/invariants:** An accepted trusted interruption still does not advance `last_ts`, populate normal `seen`, change `state`, `last_alert_ts`, `incident_seq`, notifications or cooldown; only streaks, dedicated registry and sanitized audit. Invalid/foreign/malformed/replayed samples do not reserve IDs. F2 malformed input, F3 explicit/absent rule, D1 replay-before-watermark, UTC, cooldown +899/+900/+901, new incident after RECOVERED, snapshot/replay, and `PinnedS1Evaluator=S1_EQUIVALENCE_FIXTURE_ONLY` remain within offline bounds.
